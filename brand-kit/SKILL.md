# Tadpod design system skill

## What is inside

Use `DESIGN.md` for visual rules, `BRAND.md` for the implementation contract, `brand.json` for authored metadata, and `system/variables.css` for generated tokens. Review both component kits before introducing a new pattern.

## Source context

The system combines the pasted `context/input-DESIGN.md` with bounded GitHub evidence in `context/github/dylmarriner-tadpod.md`. The source product is an operational business-management platform; preserved source examples live under `source_examples/`, preserved icons under `assets/`, and the applied shell under `ui_kits/app/`.

## When to use

Use this system for Tadpod web pages, product UI, forms, navigation, cards, and data-heavy surfaces where clarity and restrained emphasis matter.

## How to use

Start with a white canvas and Inter. Build on the 8px grid with 8px corners and 1px borders. Use `#1677ff` only for primary actions, links, selected states, and key emphasis. Keep controls at least 44px tall, provide visible focus states, and collapse dense layouts responsively. For the futuristic variant, use dark instrument panels, compact telemetry labels, and controlled motion while keeping the data hierarchy calm.

## Design system highlights

The system is clear, capable, direct, and low-drama. Prefer plain-language labels and specific verbs. Avoid gradients, ornamental shadows, hype, and decorative UI without a task. One primary action should lead each viewport.
